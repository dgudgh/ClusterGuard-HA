## 修改范围与验证计划

1. 合并helper的重复归档扫描，保留私有临时目录清单、tar失败检测以及完整路径/单根/受管标记保护；独立解包仍在验证之后。补充归档检查、解包、初始化与启动阶段耗时，日志不包含命令参数或凭据。
2. 按实际SHA256复用已存在的数据库介质，内容不一致时安全重新分发并验证；拒绝符号链接，不以文件名或大小代替摘要。安装流程及控制面仍保留原有安全顺序。
3. 真实tar正反例：有效包、损坏包、绝对路径、父目录越界、多根、顶层散文件、路径别名、覆盖受管标记；失败必须在停服务或删除目录之前。复用同内容/异内容/损坏包/符号链接及失败返回码测试。
4. Go受影响包与全仓、SOURCE严格门禁及变异、Shell语法、Markdown台账、HTML与许可门禁；独立审查实际diff。使用同一份原厂介质在独立路径对比旧/新归档流程，不改运行数据库或生产cnf，不将该对比冒充全新三节点安装。
5. 源码、新制品及整体现场验收分别记录。旧3.1.3.5及所有已交付包不可覆盖重建；若构建新候选，使用新四段版本/RPM身份，先完成适用构建清单。

## 实现与独立审查

MySQL原生helper将两次完整tar目录读取合并为一次0600临时清单；先确认完整压缩流成功，再执行原有awk路径检查，随后才进入停服务、残留处理与解包。退出清理清单。解包继续使用原有所有权/权限保护。增加归档检查、软件解包、配置验证、初始化和服务启动耗时；保留原始返回码与凭据脱敏。

集成检查发现原安装器成功时吞掉helper输出。仅MySQL安装步骤新增可选实时中继，白名单完整匹配数字端口、固定阶段、返回码和秒数；其他helper维持原行为。任意raw输出只留内存，失败后仍脱敏并截取末120行。0600临时状态文件只存数字退出码。真实管道握手测试确认阶段行在远端结束前可见，raw凭据不能提前输出；失败37原码与脱敏均保留。

安装器先计算本地SHA256，在每台节点实际重算目标摘要，相同才复用。异内容通过同目录0600临时文件上传，远端校验后设root:root/0640并原子发布，损坏或传输失败保留旧件。目标和各级目录符号链接拒绝。已有/data和/data/packages仅检查，不修改属主、组或模式；必须由root拥有且组/其他用户不可写。引擎专用缓存目录校正并验证root:root/0750。

独立审查发现的引擎目录属主与祖先目录可写问题均已修复，并新增正反测试和变异；最终审查未发现剩余阻断。生产模板、数据库参数、初始化证明、并发锁、writer lease、复制及VIP流程均未改。
