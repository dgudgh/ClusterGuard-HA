## 本次不变量与设计范围

- 旧格式残留不自动猜测、不把rebuild改成true；已有完成初始化、未知状态、配置/身份不匹配或运行进程必须保护原数据。
- 新流水原子记录初始化准备/调用/明确失败/成功及完成阶段，并绑定端口、实例/软件路径、生产配置、介质摘要、原空目录身份与失败日志。只有确证本次从空目录开始且原生明确失败的记录可以自动保留隔离。
- 初始化中断但没落盘明确失败（包括初始化成功后记录前断电）仍属未知状态，不能作为自动重建凭证。
- 隔离必须在原父目录以唯一名称原子移动，保留原配置、数据、日志、binlog/relaylog及阶段记录；不得删除已有数据来让流程继续。
- 修正受管残留的错误信息，不再错误叫unmanaged；输出日志与对应处理边界。
- 当前旧格式现场先只读取证，准备精确保留与续装计划；此前用户要求自己更新仍有效，未明确接手续装前不擅自执行三节点安装。

## 回归计划

1. 用真实初始化失败残留复现旧目录判定失败，验证新记录可保留隔离、旧记录默认拒绝。
2. 覆盖已完成/initializing窗口、旧错误后成功启动、配置/介质/路径/inode不匹配、标记或路径symlink、进程/监听、foreign/drop-in单元、隔离失败和重复重试；拒绝必须证明数据原字节不变。
3. 完整MySQL helper真实安装到独立诊断实例，覆盖initialize、服务就绪、口令及只读角色，不用仅初始化测试代表整步安装成功。服务隔离与清理仅限自建诊断实例。
4. 全仓Go/vet、Shell、源码门禁/变异、许可、Markdown台账和生成页；若新介质必须新身份，保持旧制品和现场数据。
