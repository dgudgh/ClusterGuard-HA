ClusterGuard HA 2.2.40 发布说明#

发布日期：2026-08-28

v2.2.40 修复容器数据面执行图形化滚动升级时的三项阻断问题，不改变数据库复制、业务入口或高可用策略。

修复内容#

  • Raft 多数派由当前 Leader 确认，Follower 只要求就绪并识别同一个 Leader，不再错误要求每个 Follower 返回 Leader 专属的 quorum_confirmed=true；
  • 宿主机固定 UUID 与 Docker Swarm、Kubernetes Agent 的逻辑 UUID 分开验证；
  • 所有控制节点必须观察到完全一致的逻辑数据节点清单，并将每个逻辑节点的 ip_address 映射到明确提供的宿主机清单；
  • 允许同一宿主机承载多个容器数据库实例，同时继续拒绝未知宿主机、额外 Raft 成员、重复逻辑 UUID 和不一致观测；
  • 特权升级 Helper 生成的状态、输出和事件记录以 root:clusterguard 0640 发布，控制台服务可持续读取真实计划和升级结果，不再出现“后端成功、页面无记录”；
  • 继续保持 Follower、纯数据节点、Leader 的固定滚动顺序，升级失败自动停止并使用包内旧 RPM 回退。

升级说明#

正式 2.2.39 环境使用本 Release 提供的签名 .cgupgrade。历史实验室 2.2-38.field3 的 RPM 记录、运行时合同和旧版升级公钥与正式基线不同，必须使用现场限定的 .cgpatch 桥接包和一次性升级通道引导器，不得将通用离线安装包上传到版本更新页面。

图形化升级必须先生成只读计划。真实执行期间平台会进入维护门禁：

系统升级期间无法进行自动切换，请注意关注。

数据库进程、复制关系和业务 VIP 不会因 ClusterGuard 控制软件滚动升级而主动停止或重建。

验收边界#

  • 升级器脚本自动化测试覆盖原生节点、容器逻辑身份、同宿主机多实例、Follower 多数派语义、额外控制节点和额外数据宿主机；
  • 192.168.102.152-154 实验室环境需完成页面上传、只读计划、滚动执行、版本一致性、Raft 多数派、数据库主从和业务入口复核后，才能作为该现场的升级验收结论；
  • 代码测试通过不等同于客户生产环境验收。
