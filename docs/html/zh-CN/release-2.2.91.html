ClusterGuard HA 2.2-91：拓扑切换被全量操作日志阻塞#

日期：2026-09-08。源版本：2.2-90；目标版本：2.2-91 x86_64。由用户手动上传升级，不部署现场。

现场证据#

通过用户已登录的 Chrome 新诊断标签页，只读切换到 swarm-pg16，查看 DevTools Network；未执行 discover、切换主库、升级或数据库修改。设置页面确认本机当前版本为 2.2-90。

这一次集群选择的请求耗时：

请求 耗时 网络传输
集群详情 26 ms 9.3 kB
topology 5 ms 6.6 kB
health 3 ms 1.6 kB
candidates 2 ms 3.9 kB
metrics 2 ms 1.7 kB
operations?cluster_id=... 2.34 s 3,027 kB

拓扑本身已经快速返回，但前端等待全量操作记录完成才统一绘制节点。因此页面空白等待主要被本次 3 MB 操作记录拖住，并非这次拓扑接口本身耗时数秒。

既有加载代码还会保留上一轮“集群状态已更新”的 toast；进入下一轮 loading 后该提示没有清除。重试按钮虽然设置 hidden，但按钮的 display 样式覆盖了浏览器默认隐藏，导致加载中仍可见。

此前恢复经典配色只回退样式，保留了这条等待链路。不能据此断言所有更早版本的卡顿都由同一原因造成，也没有取得用户所称更早快速版本的同条件现场数据。日志增长会放大该问题，但历史增长量本轮未测量。

修复#

  1. 详情和拓扑并发读取；取得当前请求的拓扑后立即绘制，健康、候选、指标与操作摘要仍继续核对。未完成或证据不一致时操作按钮保持锁定，不伪造健康与可执行状态。
  2. 操作列表增加显式 view=summary。保留全部记录、身份、状态、旧主库、首个阻断原因和复核结果；不重复传输执行步骤、完整验证和尝试明细。
  3. 原有默认列表 API 仍返回完整记录，不改变外部调用协议。单条详情仍从 /api/v1/operations/{id} 返回完整公开诊断证据。
  4. 点击“原始返回”后按需读取详情；失败可重试，同一展开块再次打开不重复取数。未展开时既不读取详情也不提前 stringify 完整证据。
  5. 切换集群中止旧读取请求，并保留请求代次校验，避免旧请求占用连接和覆盖新选择。
  6. 开始加载时撤销过期成功提示，正确隐藏加载中的重试按钮。

不删除或裁剪历史记录，不变更安装包保留策略，不放宽 fencing、Raft 多数派、writer lease 或后端操作授权。

回归结果#

  • go test ./internal/api ./internal/store：通过，API 1.661 秒，store 7.693 秒。
  • 摘要 API 大记录测试：同样保留 12 条记录，完整列表 856,573 字节，摘要 8,017 字节。按集群过滤仍保留 6 条；单条完整详情可取，底层记录未修改，失败与复核信息保留，密码和 token 测试脱敏通过。
  • 从已发布 90 RPM 中提取实际内嵌 HTML，与本次 HTML 使用同一隔离模拟 API 对比。400 条原始记录共 3,235,601 字节，模拟完整日志传输延迟 2.4 秒。
隔离浏览器测试 已发布 90 修复 91
初次加载完成 4,994 ms 75 ms
三次切换到节点显示 2,435 / 2,433 / 2,427 ms 17 / 8 / 7 ms

摘要响应刻意保持未返回时，节点 5 ms 显示，操作锁定、“读取中”保留；无过期成功提示、无加载中重试按钮。旧请求取消、原始详情失败重试、400 条记录完整计数和“加载更多”通过。

这是隔离模拟测试结果，不是承诺现场加载只需 7 ms，也不是 91 的现场升级验收。

另通过六种宽度的工具栏交互、24 组页面截图、12 次集群切换、超时/503/409/乱序、升级弹框空态与独立日志滚动、恢复界面确认和阻断回归。升级器脚本没有修改，本轮不重复执行现场滚动升级。

发布与验收要求#

  • 签名包包含原版 90 回退 RPM、91 目标 RPM和引导升级器，必须核对受信公钥、清单、载荷摘要与嵌入页面一致性。
  • 本次交付仍需用户通过控制台上传 .cgupgrade，完成现场版本、加载耗时、日志计数和展开详情的验证。本轮未部署，不把隔离 UI 测试写成现场数据库验收。
  • 之后凡修改拓扑加载链路，必须跑含大日志体积、慢辅助请求、旧请求取消和失败重试的性能测试，不能只用几条即时返回的示例记录宣称无卡顿。
