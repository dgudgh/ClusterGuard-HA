ClusterGuard HA 2.2-95#

日期：2026-09-09。交付范围：日志集群联动修复和用户已确认的日志工具栏优化。供用户手动升级，不包含现场安装。

旧版对比#

  • dc1a57a：日志按顶部当前集群查询。
  • bc0546a：新增默认 logClusterId: 'all' 并改为独立全局日志，引入联动回归。
  • 从已交付的 2.2-94 RPM 提取实际控制台 HTML，确认仍继承默认全部集群。已逐项对比该包与本次目标包，静态页面只改动用户确认的日志工具栏，其余页面保持原有风格。
  • 完整证据见 日志集群联动回归记录。先前修改前没有完成历史比较的流程违例保留记录，不倒填。本轮在对照完成后，按用户继续交付要求进行复核、构建和本地验证。

修复内容#

  1. 默认日志跟随顶部所选集群，MySQL 与 PostgreSQL 不再混显。
  2. 切换集群立即清空旧列表、游标并取消旧请求，晚到响应不得混入新集群。API 返回其他集群记录时拒绝显示并提示重试。
  3. 同一集群刷新保留已加载页及展开的详情；日志页隐藏时不预取，进入日志页才读取。
  4. 保留用户显式查看全部集群的入口；再次切换顶部集群时恢复跟随。
  5. 继续使用 20 条服务端分页、详情按需读取和全历史筛选。完整保留日志，未将安装包保留三个版本误用成日志保留三条。
  6. 工具栏按已确认样式统一为左侧标题与计数、右侧搜索与筛选；窄屏自动换行。没有恢复米白绘本主题，也没有重做其他页面。

本次不修改数据库恢复策略、签名协议、权限、fencing、健康判断、维护门禁或多数派要求。此前 P0 的真实数据库现场验收不属于本次局部回归的通过声明。

本地验收#

使用实际控制台 HTML 和隔离 API fixture，不对真实数据库执行操作：

  • 日志联动 9 项：首次集群范围、立即清空、同集群刷新、隐藏页、迟到分页、显式全局、12 次 MySQL/PG 切换、错误范围拒绝、未选择集群。
  • 分页 7 项：第一页 20 条、详情按需、重复点击、失败重试、全部 83 条完整遍历、全历史筛选及旧请求丢弃、桌面与移动布局。
  • 1,000 条日志的上下文隔离测试与 320–1920px 的 11 个工具栏布局场景。
  • go test ./...、go vet ./...、go test -race ./internal/api ./internal/store -count=1 全部通过。本轮脚本包测试用时 249.474 秒，存储竞态测试用时 106.720 秒；未用跳过测试缩短交付时间。
  • 最终命令结果、浏览器结果和包验证报告随交付目录的 evidence/ 与 package-verification.json 一并提供；未执行的现场步骤不得计入通过。

手动更新与现场限制#

  1. 在控制台核实三台控制节点均为 2.2-94，且架构为 x86_64。现场版本本轮未登录查询，截图不能代替版本核实；其他来源版本不要使用此包。
  2. 在“设置 → 版本更新 → 升级”选择 .cgupgrade 文件，上传并校验；校验完成后执行滚动升级。不要用直接安装 RPM 绕过升级门禁。
  3. 升级后确认目标版本为 2.2-95。在日志页切换 MySQL/PG，确认范围跟随、没有混入其他集群；检查加载更多、搜索与原始详情。

没有 SSH、没有更换现场信任公钥、没有清理任何现场日志、没有上传或执行现场滚动升级。现场连续可用性、实际 PostgreSQL/MySQL 刷新耗时和灾难恢复场景尚不能由本次本地测试证明。
