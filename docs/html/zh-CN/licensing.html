许可与合规#

本章说明 ClusterGuard HA 适用什么许可、使用它会产生什么义务、以及企业客户需要注意什么。 内容依据许可条文本身，不构成法律意见；条款解释有疑问时请咨询你自己的法务。

一句话#

ClusterGuard HA 采用 AGPL-3.0-only。你可以自由使用、修改、收费分发；但一旦你把修改后的 版本对外提供（包括只作为网络服务提供），你就必须把对应源码按同一许可开放出去。

1. 本项目适用什么许可#

项目 值
SPDX 标识 AGPL-3.0-only
全称 GNU Affero General Public License, version 3
许可全文 仓库根目录 LICENSE（官方原文，未做改动）
版权 Copyright (C) 2026 dgudgh
第三方组件 THIRD-PARTY-NOTICES.md

选 only（而非 or-later）是刻意的：它把许可版本钉在 v3，未来 FSF 发布新版不会自动适用。

packaging/rpm/nfpm.yaml 的 license 字段、RPM 内 /usr/share/doc/clusterguard-ha/LICENSE、各 README 与本页陈述的是同一件事。

2. 使用者的义务速查#

你做的事 需要开源吗 依据
自己内部部署运行，不改代码，不把副本交给外部 不需要 未发生分发，§13 也未触发
改了代码，只自己内部用，不对外提供服务 不需要（但改动仍受 AGPL-3.0-only 约束） 未发生分发
改了代码，并让人通过网络（网页、API）访问它 必须向这些使用者提供对应源码 §13
把二进制或源码副本交给第三方（客户、合作方、镜像站、嵌进自家产品） 必须：附 LICENSE、标注改动、提供对应源码 §4–§6
把它打包进你对外销售的产品 必须，且你整个组合作品对外提供的部分仍要满足本许可 §5、§13
只是收钱 不受限制，收费本身完全允许 §1、§4

两点必须说清楚：

  • 「对应源码」是你版本的全部源码，包括你做的修改，不只是上游原始代码。
  • §13 的触发条件是修改 + 通过网络交互。若你原封不动地跑官方 RPM，§13 不会额外给你加 义务；但一旦发生分发，§4–§6 的义务立刻生效。

3. 三种典型场景#

3.1 内部部署，不改代码#

拿到离线介质，装到自己的机房，运维自己的数据库。不产生对外开源义务。

3.2 修改后对外提供网络服务#

你把控制台改造后开放给另一个部门、子公司或外部客户通过浏览器/API 使用。必须让这些使用者 能取得你改造后的完整源码，通常做法是在控制台里放一个显眼的「源码」入口，并在其中提供可取 得的地址。这是 AGPL 相对 GPL 的关键增量，也是本项目选 AGPL 的原因。

3.3 再分发#

把 RPM 或离线介质转给第三方、或作为你产品的一部分卖出去。必须：

  1. 随附完整的 LICENSE；
  2. 明确标注你做了哪些改动及日期；
  3. 提供对应源码的取得方式；
  4. 不得追加与本许可冲突的限制条款。

4. 收费不受影响#

AGPL-3.0-only 不禁止商业使用，也不禁止收费。你可以按任何价格出售、提供付费支持、 提供付费托管。它限制的是「拿了代码却不让别人拿到代码」，不是「不许赚钱」。

5. 企业客户须知（重要）#

这一条必须明说，因为它直接影响交付政策：

在 AGPL-3.0-only 之下，收到软件的一方在法律上有权自由再分发它，你无法用版权阻止。

因此，本仓库 docs/zh-CN/version-release-policy.md §3.1 规定的「升级包只对签约企业客户交付、 只留本地、不上传公开渠道」是交付与支持策略，不是许可证层面的限制。签约客户仍然受本许可 约束；维护者的商业价值来自版本交付、生产验证、支持响应与责任承担，而非版权封锁。

若你的商业模型需要「客户不得再分发」这种约束（即传统闭源授权），AGPL-3.0-only 做不到， 需要改为专有许可或双授权 —— 见 §8。当前状态是 AGPL-3.0-only，这一点没有含糊空间。

6. 第三方组件#

二进制内链接了 15 个 Go 模块（4 个 MPL-2.0、11 个 MIT/BSD-3-Clause），离线介质还捆绑了 Rocky Linux 8 的 271 个依赖 RPM，并可能嵌入 MySQL / PostgreSQL 的官方安装包。这些组件的 许可是独立的，不因本项目采用 AGPL 而改变。完整的逐项清单、版权人与取得方式见 THIRD-PARTY-NOTICES.md：

  • MPL-2.0 副本随附于 docs/licenses/MPL-2.0.txt，并由 RPM 安装到 /usr/share/doc/clusterguard-ha/MPL-2.0.txt。
  • ClusterGuard HA 通过执行各数据库自带的命令行客户端来操作它们，不链接任何厂商客户端库， 因此各数据库厂商的许可不约束本项目自身代码。
  • 再分发捆绑的 MySQL Community 包会带来 GPL-2.0 义务，该义务属于执行分发的那一方。

7. 如何取得源码#

git clone https://github.com/dgudgh/ClusterGuard-HA.git
git checkout <BUILD-INFO 中的版本>     # 例如 v2.2.103

BUILD-INFO 与 build-info.json（随每套介质发出）记录了版本、提交与构建时间，用于把二进制 精确对应回某个提交。这是 §13「对应源码」的可操作形式。

8. 维护者操作：改协议与双授权#

本仓库的 200 个提交全部出自同一作者，无他人署名，不存在需要征得同意的第三方贡献者。 因此维护者可以：

  • 重新授权：把 AGPL-3.0-only 换成别的许可（如 Apache-2.0、专有），只需替换 LICENSE 并同步下列各处；
  • 双授权：对不愿接受 AGPL 义务的企业客户另行签发商业许可，同时继续以 AGPL 发布社区版。

一切协议变更都必须在同一次改动中同步以下位置，否则仓库自相矛盾：

位置 作用
LICENSE 权威全文
packaging/rpm/nfpm.yaml 的 license RPM 元数据（SPDX 标识）
packaging/rpm/nfpm.yaml 的 contents 保证 LICENSE 进 RPM
scripts/build-clusterguard-rpm.sh 把 LICENSE 拷进打包 stage
scripts/build-clusterguard-offline-kit.sh 把 LICENSE 放进离线介质
README.md / README.zh-CN.md 公开首页陈述
docs/zh-CN/licensing.md / docs/en-US/licensing.md 本页双语版
THIRD-PARTY-NOTICES.md 第三方清单与许可兼容性结论
AGENTS.md 后续 agent 的硬性规则

改完必须跑：

node tools/verify-license-consistency.cjs

9. 免责与不担保#

软件按「现状」提供，无任何明示或默示担保。许可是不可撤销的：一旦某人依 AGPL-3.0-only 取得了你的版本，你不能事后收回他对该版本的许可。因此在公开发布前确定好协议， 比发布后修改更重要。
