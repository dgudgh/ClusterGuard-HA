# ClusterGuard HA 2.2-70：维护门禁恢复与 PostgreSQL 拓扑修复

> 状态：真实浏览器上传与验签通过，但只读升级计划仍被遗留任务阻断，已由 2.2-71 取代。请勿执行 2.2-70。

构建日期：2026-09-07。来源版本：2.2-68。架构：Linux x86_64。

## 修复范围

1. 修复 Durable Workflow 在执行前进程中断或审计失败后遗留永久 `running` 记录的问题。
2. 新增 Leader-only 陈旧任务协调器。超过 30 分钟、没有活动分布式租约的执行前记录会原子收口为失败历史，不再永久阻塞升级维护门禁。
3. 升级器逐项输出控制面门禁事实和违反条件，不再把活动任务误报成某个 PostgreSQL 节点异常。
4. 旧版本引导升级器只对严格匹配的陈旧自动恢复执行前记录提供一次维护期引导；新 Leader 必须完成原子收口，最终仍要求活动任务为零。
5. 保留 2.2-69 的 PostgreSQL 双端原生身份、WAL sender/receiver 关联、Timeline 和 streaming 证据修复。健康判断、fencing、writer lease 与多数派授权没有放宽。
6. 升级材料默认保留最近三个版本；操作日志和审计历史不受该保留数量影响。

## 安全边界

- 不自动清理人工任务、新鲜任务、执行阶段及之后的未知任务或有活动租约的任务。
- 不从升级脚本直接修改、删除 Operation 或 Raft 元数据。
- 不为完成升级而削弱维护门禁、数据库 fencing、VIP 或自动故障切换规则。
- 诊断日志不输出控制 Token、密码、连接串、Cookie 或 passfile。
