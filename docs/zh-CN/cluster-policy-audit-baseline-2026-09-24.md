# 集群策略提交与审计对照（2026-09-24）

## 基线与范围

- 当前工作树：`codex/2.2-postgresql`，基线提交 `467e533`（2.2-103）；集群策略是本次尚未提交的新增代码，旧版没有该 API。
- 旧版正确行为：`internal/store/clusters.go` 的集群退役和 `internal/store/operations.go` 的操作复核，都在同一份快照中追加审计并提交。`internal/store/repository.go` 的 `RecordAudit` 本身则是一次独立快照提交。
- 当前新增路径：`PUT /api/v1/cluster-policy` -> `writeClusterPolicy` -> `PutClusterPolicy`（提交策略）-> `recordClusterPolicyAudit`（独立提交并忽略错误）。第二次提交失败时，策略已生效而审计缺失。现有测试只检查两个提交都成功的情况。
- 作用范围：新增策略当前按引擎存储在整个控制面的复制快照中，不含集群 ID；同一控制面内所有同引擎集群会受到影响。旧版没有策略，因此也没有可继承的单集群策略语义。
- 页面读取路径：`fetchClusterPolicy` 捕获错误后仍调用 `renderClusterPolicy`；`clusterPolicyCurrent()` 把未读到的策略当空对象，保存时会提交替换式载荷，可能清空另一个引擎的覆盖。旧版没有该编辑器；现有新增测试只检查静态字符串。

## 回归与拟改范围

1. 将策略及经脱敏、长度校验的审计事件放进同一份复制快照，只执行一次共识提交；失败时两者都不得发布。清除覆盖也应记录审计，空策略上的重复清除是无操作。
2. 在设置页明确写出策略按引擎作用于整个控制面，不随顶部选中集群缩小范围。
3. 用存储层测试覆盖成功、清除、共识提交失败与跟随者复制；API 测试覆盖正常写入与错误响应。保留权限、Raft 多数派、自动切换和既有快照兼容门禁。
4. 策略未成功读取时禁用保存/清除；读取失败要显示错误，不得把未知状态当空策略。无效数值不得悄悄变成零覆盖。浏览器检查真实点击。

无法在旧版复现此新增 API；以上旧行为依据 `git show 467e533` 的源码，当前缺陷依据工作树源码与新增测试。这里是本轮修复前的对照，不倒填为前序修改的事前记录。
