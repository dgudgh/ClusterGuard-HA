# ClusterGuard HA 2.2.43 发布说明

> **语言：** [English](../en-US/release-2.2.43.md) | 简体中文

发布日期：2026-08-28
版本：`2.2-43`

## 版本概述

`v2.2.43` 修复滚动升级执行后状态退回“已上传”的问题，并建立签名包内升级器合同。升级编排修复从此可以在目标 RPM 安装前生效，不再由源版本中可能已经过时的脚本主持整个升级。

本版本只更新 ClusterGuard 控制面、Agent 和升级工具，不修改数据库软件、数据目录、复制关系或业务入口。

## 主要变化

- 新 `.cgupgrade` 在发布签名覆盖的清单中声明包内引导升级器、协议和 SHA-256，缺失或被篡改时在进入维护状态前拒绝执行。
- 源节点升级器只负责安全解包、签名和摘要校验，随后把计划、滚动、收敛等待、续跑和回退交给验签后的包内升级器。
- 控制台在上传和执行两个入口同时检查引导升级器合同，历史遗留的无引导器 `.cgupgrade` 不能绕过新检查；旧 `.cgpatch` 仅保留兼容入口。
- 任务状态文件存在但不可读、损坏或升级包 ID 不一致时，控制 API 返回“操作结果需要验证”，并保守保持维护告警，不再把任务伪装成“已上传”。
- 滚动进度按当前活动节点计算，所有节点完成后稳定显示 `100%`。

## 升级边界

- 从 `2.2-42` 升到 `2.2-43` 时，由 `2.2-42` 中已经具备重试、续跑和状态权限修复的执行器完成首次升级。
- `2.2-43` 安装完成后，后续签名升级包才会在执行前切换到包内升级器；控制台会显示“引导器 v1”。
- 升级维护期间继续暂停自动故障切换，全部节点、数据库主从、业务入口和 Raft 多数派复核通过后才释放维护门禁。

## 升级路径

当前运行 `2.2-42` 时，上传：

```text
clusterguard-ha-2.2-42_to_2.2-43.x86_64.cgupgrade
```

先生成只读计划，再于维护窗口执行滚动升级。若状态显示“操作结果需要验证”，不得重复发起升级，应先查看升级事件和原始输出并核对现场版本。
