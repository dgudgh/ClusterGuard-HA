# 集群自动切换与实例权重

[English](../en-US/instance-failover-policy.md) · [前端入口](../development/frontend/settings/instance-failover.md) · [后端入口](../development/backend/settings/instance-failover.md)

## 在页面上设置

先在顶部选择数据库集群，然后进入 **设置 → 运行参数 → 自动切换策略 → 当前集群自动切换与实例权重**。以管理员登录，点击“解锁策略编辑”，修改后保存。换集群、刷新、会话变化和保存结束后重新锁定；修改仅作用于当前集群，不同时修改其他同引擎集群。

- 开启集群自动切换：只有原主库故障满足证据窗口、候选安全条件、Raft多数派和旧主隔离等条件时，才会自动选择新主库。
- 关闭集群自动切换：不会创建新的自动切主，仍可走原页面手动切换和安全检查。
- 实例“参与自动切换”：以数据库实例UUID为对象。同一主机的MySQL3306与PG5432分别设置，不使用控制器ID、IP或主机名代替实例身份。关闭参与只限制自动升主，仍保留发现、监控、复制重挂和手动切换能力。
- 权重为0到1000整数，默认100，数值越大越优先；0是最低权重，退出自动候选须关闭参与开关。
- 高权重实例恢复后不会自动抢回主库。保存策略不会立即切主，也不改变现役writer或VIP归属。

现有全局“引擎级维护暂停”继续优先：即使本集群开启自动，同引擎全局维护暂停期间也不会自动切换。无Agent/fencing、Raft、发现或对应引擎能力时，不能通过此开关补齐缺失能力，页面显示未就绪，服务端拒绝开启。

## 权重与数据安全

权重不能绕过复制健康、维护状态、GTID、PG系统身份/时间线/WAL、旧主隔离或多数派。MySQL优先保留原风险等级和事务完整性排序，PG优先保留WAL完整性排序，再在相同安全/数据层级内比较权重，同权重沿用原排序和UUID决胜。因此高权重落后或不安全的实例不会越过更完整的合格实例。

首次没有显式集群策略时沿用启动配置，候选默认参与且权重100；保存后未在规则中列出的新发现实例默认不参与自动升主，必须明确启用。新增/替换实例得到新UUID，不会继承旧IP的参与资格。启动默认关闭且执行前置齐全时，保存本集群开启即可在下轮生效，无需修改三份配置或重启。

## 升级、并发与失败

本功能当前仅支持MySQL和PostgreSQL，原生VIP和gateway都使用同一候选策略。先让全部投票控制节点升级到支持实例策略的版本，再配置；保存前逐一核验当前Raft成员的协议版本与身份，旧版本、失联、未知协议或身份错误均拒绝保存。保留实例策略时不得回退到不认识该字段的旧控制器。

保存使用策略自身revision进行CAS，不把频繁发现修订当成策略修订；冲突后重新读取，不覆盖他人的配置。实例必须属于所选集群，提交与审计同一Raft快照原子生效；集群操作正在执行、升级/参数下发维护期间拒绝修改。自动选候选的策略修订还会在执行前重新核对，防止选完后策略变化仍按旧目标执行。

已进入隔离/提升等不可逆阶段的任务必须按原保护流程收尾；此开关不是强杀执行器或移除租约/隔离的入口。具体实现、测试阶段和现场范围见[本轮记录](../development/instance-failover-policy-2026-11-03.md)；隔离浏览器和单元回归不等于现场切主验收。

未保存本功能策略前，签名文件回退仍沿用原流程；保存后，关闭自动切换不等于清除策略，不能据此直接降级到旧控制器。

网关模式的数据库故障接管使用受签名约束的数据库Agent直接隔离：MySQL验证持久只读/重启保护，PG验证原生停服；数据库节点不挂载网关固定VIP。Agent不可达或隔离证据不足时，仍要求可验证的外部隔离，不能仅按权重强切；本轮未为网关开放原生VIP模式的失联Agent授权超时兜底。
