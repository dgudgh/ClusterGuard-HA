**尚未发布 GitHub Release，签名 ART 与真实三节点 FIELD 仍 OPEN。** 本地源码、原生隔离检查、完整介质结构检查分别记录；人工三节点安装通过之前不能作为生产交付已验收。

## 本次修复

- 不再用 `data/mysql/` 存在判断数据库是否初始化完成。MySQL失败初始化也可能创建该目录；旧提示错误地将受管残留叫作 unmanaged。
- 原子记录安装阶段，绑定节点、端口、路径、原厂介质、生产配置、目录身份及失败数据/日志证据。只允许已证实的空目录准备失败或明确非零初始化结果续装；初始化结果未知、已完成或证据改变时保留原数据并拒绝重新初始化。
- 续装先把整个失败实例移入同父目录唯一备份，保留数据、配置、日志和阶段记录，不再凭 `.installing` 删除受管的部分数据。软件归属及服务停用保护保持生效。
- 同端口安装由稳定父目录 `flock` 串行化；RPM显式依赖系统util-linux，MySQL数据节点预检缺失时提前报告。
- 旧格式半初始化残留在时钟、RPM、防火墙变更前就明确阻断，给出原日志与保留边界，避免每次重试先做一轮无效安装变更。

继续包含3.1.3.3的严格运行配置验证、仅初始化临时副本的半同步选项兼容及密码脱敏诊断。生产主从cnf普通参数保持批准版本，只调整部署路径、唯一节点身份与已确认的只读启动保护。

## 对当前旧失败目录的处理

3.1.3.2/3.1.3.3没有可靠阶段记录，不能伪造为新失败证明。先人工确认无MySQL进程、无3306监听、确属此次全新失败且无业务数据，并确认实例自身和内部没有挂载（包括 bind mount），再将整个实例目录保留改名；`/data` 这类祖先挂载允许。保留原state、secrets和work-dir，用本介质复用原安装命令。不要删数据、管理标记、站点状态或设置 `rebuild=true`。

详细边界与交付前人工清单见[安装手册 §12.10](offline-rpm-install.md#1210-初始化失败后的续装与交付前人工测试)，全部命令参数见[独立参考](offline-installer-parameters.md)。当前三台真实数据库目录仍由用户操作，本轮未接管安装。

## 介质内容与验证

文件为 `clusterguard-ha-3.1.3.4-offline-linux-x86_64.tar.gz`、同名摘要、RPM、`RELEASE-INFO`、`SHA256SUMS` 和 `verification.json`。tar内含安装器、五个程序、systemd单元、辅助脚本、生产模板、静态jq、离线基础运行依赖、公钥、许可证与中英文安装命令参考。

数据库厂商包默认不嵌入。现场提供批准的原厂完整包及摘要，通过 `-r FILE` 明确指定或按规则从 `/opt` 发现。默认软件 `/usr/local/mysql`、数据根 `/data`；自定义目录须同时满足目标系统的权限及SELinux策略，不能用关闭SELinux代替现场验收。

本次检查结果、原始日志和源码基线见[开发任务](../development/mysql-install-resume-2026-10-15.md)。完整helper原生隔离测试使用独立端口/目录和临时systemd桥接，检查实际MySQL启动及账号，不代表三节点复制、VIP、切换或灾难恢复已完成。完整介质结构检查不替代生产签名ART验收，未签名RPM及现有验收模型限制仍如实保留。
