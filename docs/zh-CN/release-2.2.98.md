# ClusterGuard HA 2.2-98：操作锁复审修复

2026-09-09。只生成本地签名升级包，用户手动更新。2.2-97 候选包已撤回，不覆盖原包，也不要求先装 97。

## 根因与修复

修改前对照旧提交 `dc1a57a`、96/97 归档页面和当前工作树，记录见 [操作锁复审](operation-lock-audit-98.md)。本次业务代码修改仅在 `internal/api/console.html`，不改页面静态结构/CSS，不改数据库恢复算法或后端安全门禁。

1. **刷新等待期间仍可操作**：原 `refreshDiscovery` 等 discover 返回才重锁，失败时不重锁。现在点击时立即撤销旧授权和证据；失败保持锁定，旧集群迟到响应不能刷新/重锁新集群。
2. **退出挂起期间旧预检仍会提交**：原 `logout` 等响应后才撤销授权。现在退出开始即锁定，pending 时不能再次解锁，退出失败不恢复旧授权。
3. **旧会话响应影响新登录**：请求绑定登录代次与用户，旧成功/401/错误响应被忽略；会话更替中止旧集群读取，目录写回检查所属会话。
4. **恢复明确拒绝后一直等待**：明确未受理的客户端错误清除等待和确认，必须重新预检；5xx、断连、202 已受理但状态未推进时只查询持久化任务，禁止自动重提。

保留 96/97 已修复的危险操作入口锁、最终提交守卫、绑定用户/集群/目标、重复提交阻断和受限旧计划重试。普通切换、旧主回挂、复制修复、灾难恢复都遵循显式解锁；关闭窗口或重新锁定不会取消后端已经受理的任务。前端防误触不替代后端权限、CSRF、审批、维护门禁、租约和多数派验证。
