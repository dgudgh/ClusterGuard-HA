## 对照及待复现问题

已读取 AGENTS.md、发布清单、97 修改前记录，比较 `dc1a57a` 旧实现、96/97 包内 HTML 与当前工作树。已有安全门禁保留，不改数据库算法或现场环境。

1. **真实刷新按钮路径**：旧版及 97 的 `refreshDiscovery` 先 await POST discover，再调用 `loadSelectedCluster` 重锁。原测试直接调用后者，未覆盖点击刷新到发现返回之间的窗口；发现失败时根本不重锁。需要模拟真实按钮的慢请求、失败、换集群和旧请求晚到。
2. **退出按钮路径**：`logout` 先 await，再 `showLogin`。之前测试直接调用 `showLogin`，没有覆盖退出请求挂起时旧预检继续提交。退出开始即应收回操作授权，失败后仍保持锁定。
3. **恢复请求明确被拒绝**：`executeDisaster` 对所有异常均保留 pendingRevision 并轮询，400/403/423 等未受理请求不会推进任务版本，造成永久 busy。明确拒绝应解除等待但不恢复 ready/确认；网络不确定或 202 受理但任务未开始时必须保持查询，禁止自动重提。
4. **旧会话错误响应**：`fetchResult` 不区分请求所属用户，旧 401 响应可在重新登录后调用 showLogin 清掉新会话。需要绑定发起请求时的用户对象，旧响应不再影响新会话。不能通过取消后台任务解决。

以上均为源码待证实项，不预先宣称运行时复现。补充实际正常执行成功、未通过验证、丢失响应后单次跟踪，避免只用后端模拟拒绝证明功能可用。

## 扩展复审及修复范围

业务修改后又增加实际预检等待期间点击刷新/退出、旧会话成功响应、404/422 拒绝、500 不确定响应及 202 尚未推进状态，使用归档 97 HTML 重新运行扩展基线（并非倒填为第一次编辑前完成）：48 个用例，28 个失败，20 个通过，证据 `.build/operation-audit/before-expanded/result.json`。其中退出挂起时，旧回挂预检返回后仍实际到达模拟执行端点，证实不仅是按钮外观问题。

- `refreshDiscovery` 在发送 discover 前调用既有 `beginClusterRequest`，立即重锁、撤销旧意图和旧证据；用请求代次隔离迟到成功/失败，失败保持锁定。
- `logout` 在网络请求前重锁，pending 期间拒绝解锁和管理员/操作员动作；退出失败也不会恢复旧授权。
- `fetchResult` 绑定登录代次和用户，旧成功/401/失败响应不影响新登录；登录切换中止旧集群读取，目录读取也检查所属会话。未注销或取消已经被后端受理的数据库任务。
- `executeDisaster` 对明确拒绝清除 pending/busy 和确认值，必须重新预检；已提交或结果不确定仍只跟踪持久化任务，不自动提交第二次。
