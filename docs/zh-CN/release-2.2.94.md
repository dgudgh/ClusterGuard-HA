# ClusterGuard HA 2.2-94：操作日志真实分页

日期：2026-09-09。沿用经典页面，不部署到现场。

## 已确认的问题

93 及此前的操作日志是浏览器分页：`view=summary` 一次返回全部摘要，前端只显示前 50 条，点击加载更多不再访问服务器。服务端生成摘要前还调用 `Operations` 深拷贝全部操作，包括完整执行证据。显示少量记录不等于只读取少量记录。

92 已将集群刷新与历史日志读取分开；94 继续保留这项修复。当前 MySQL 和 PostgreSQL 的拓扑、健康、候选和指标读取使用持久化观测，而不是每次页面刷新直接连接数据库。本次没有现场各接口耗时证据，不能将现场 PG 比 MySQL 慢直接归因于日志，也不能宣布现场 PG 性能已解决。现场 Chrome 登录已失效，已请求用户重新登录；未使用 SSH 或改变数据库状态。

## 功能变化

- 操作日志首次只请求 20 条摘要。点击加载更多才发起下一页请求，不预取后续页。
- 使用时间与资源 ID 组成的游标，避免同一时间记录顺序不稳定，或插入新记录导致页码偏移、重复。
- 搜索、集群、类型、状态筛选在服务端覆盖全部历史，改变筛选从第一页重新开始，旧请求不能覆盖新筛选。
- 完整原始返回仍只在展开该条记录时读取。翻页保留已展开详情；翻页失败保留已有记录，重试同一游标。
- 自动恢复重试先按集群和事故聚合，再分页；事故总次数不因页面截断而减少。
- 标题显示已加载事件数、全部匹配事件数和匹配原始记录数，不将页长误标成历史总量。
- 修复通用按钮样式覆盖 hidden 属性的问题；无后续页时隐藏加载更多按钮。
- 保留完整历史和原始证据，不改日志保留策略。安装包保留最近三个版本与日志完全独立。
- 运行中、待复核操作计数和旧主库身份仍从完整历史的独立轻量上下文读取，不从前 20 条推断安全状态。

## API

`GET /api/v1/operations?view=page&limit=20`

可选参数：`cursor`、`cluster_id`、`kind`、`status`、`q`。默认 20 条，最多 100 条；游标绑定筛选条件，变更筛选后复用游标返回 400。返回 `items`、`total`、`record_count`、`remaining`、`next_cursor`。搜索范围为集群、源/目标节点的名称与标识等元数据，不扫描可能包含敏感信息的原始执行证据。列表经过现有脱敏输出。

兼容保留旧的默认完整列表及 `view=summary`，新控制台不再调用它们。单条详情 API 不变。为得到精确总数，服务端仍遍历历史元数据，但不克隆或排序全量执行证据；仅保留一页候选，自动恢复事件另有按事故的聚合索引。

## 验证

- Go 测试：1,003 条历史完整遍历、时间相同的稳定顺序、新记录插入、旧记录筛选、参数/游标非法拒绝、事故跨页聚合、跨集群隔离、证据不变、旧 API 和延迟读取详情兼容。
- Chrome 加载真实 HTML、隔离测试 API：20 条首屏、无预读、无初始原始详情、重复点击保护、失败重试相同游标、展开状态保留、83 条全部可访问且无重复、最旧记录搜索、输入防抖、过期响应丢弃、桌面及手机布局。
- 1 万条记录的本地 store 基准（三次）：分页每次分配 79,408 字节、约 2.06–2.57ms；旧全量克隆分配约 47,817,736 字节、约 5.02–5.58ms。它不包含现场网络、JSON 传输或数据库探测，不能当成现场性能数字。
- 1,000 条记录、统一模拟 2.4 秒日志延迟的浏览器回归：旧 91 页面切换等待约 2.4–2.6 秒；当前页 MySQL/PG 都不等待历史日志，日志读取挂起时仍可完成拓扑刷新。此为隔离回归，不是现场时延对比。
- 全量 `go test ./...`、`go vet ./...`、store/API 分页和上下文相关 race 检查通过。沿用的安全门禁与观测不一致时锁定操作的测试保留。
