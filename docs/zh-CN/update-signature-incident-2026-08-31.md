# 升级包验签失败复盘（2026-08-31）

## 事件摘要

- 来源版本：`2.2-59`
- 目标版本：`2.2-60`
- 发生时间：2026-08-31 15:04:52
- 控制台报错：`patch signature verification failed`
- 影响：升级包在上传校验阶段被拒绝，没有建立升级维护门禁，也没有修改任何节点 RPM。
- 当前状态：根因已确认。`2.2-60` 升级包已经废弃，不得继续交付或执行；修复制品必须使用实验室现场信任链并采用新发行序号。

## 已确认事实

1. `2.2-60` RPM 构建成功，仓库完整测试通过。
2. 本地升级包的清单签名、包内 SHA-256、来源版本、目标版本、回退 RPM 和引导升级器均通过本地检查。
3. 失败的 `2.2-60` 包使用正式发布签名链，公钥 SHA-256 指纹为 `11d4f9c1c4b6989736de2001e89906414a553991b6f5a693eef1ba53f6168d7a`。
4. 当前实验室现场使用独立的实验室签名链，公钥 SHA-256 指纹为 `46ac59a2234263c1410d79e6e60d3961a5835257ea3cc6b0e1383803cae95c65`。
5. 现场此前接受并执行的 `2.2-58` 到 `2.2-59` 包可以通过实验室公钥验签，无法通过正式发布公钥验签。这证明两条信任链不同。
6. 现场控制台拒绝使用正式发布链签名的 `2.2-60` 包，与上述指纹证据完全一致。
7. 在宣布制品可用前，没有核对当前现场所使用的签名链，也没有完成一次真实控制台上传验收。

## 流程根因

直接根因是构建 `2.2-60` 时选择了正式发布签名链，但 `192.168.102.152-154` 实验室使用的是独立实验室签名链。流程上又把“本地正式公钥可以验签”错误地当成了“实验室现场一定信任该公钥”。构建时虽然使用了 `--expected-public-key`，但参数指向错误信任域中的历史发布副本，没有与上一版现场已接受制品的签名链做连续性校验。

## 强制发布门禁

以后每个 `.cgupgrade` 必须依次通过以下门禁，缺少任意一项都不得标记为可交付：

1. 从每个控制节点读取实际配置和受信公钥：

   ```bash
   trust_key="$(jq -r '.trust_key' /etc/clusterguard/update.json)"
   test -f "$trust_key"
   openssl pkey -pubin -in "$trust_key" -outform DER | openssl dgst -sha256
   ```

2. 三个控制节点的公钥指纹必须完全一致。节点不一致时先修复现场信任配置，不得继续构建。
3. 从离线签名私钥导出公钥指纹，并与现场指纹比较：

   ```bash
   openssl pkey -in /secure/offline/clusterguard-patch-signing.key \
     -pubout -outform DER | openssl dgst -sha256
   ```

4. 将现场公钥的受控副本传给 `build-clusterguard-patch.sh --expected-public-key`。不得随意选择历史版本目录中的公钥。
5. 解包新制品，使用同一现场公钥验证 `PATCH-MANIFEST.sig`，并执行 `SHA256SUMS` 校验。
6. 登录当前 Raft Leader 的控制台，从“设置 > 版本更新”真实选择并上传 `.cgupgrade`。
7. 只有控制台显示签名校验通过、来源版本和目标版本正确后，才能记录制品为“可交付”。上传验收阶段不得生成计划或执行滚动升级。
8. 发布记录必须保存现场三节点公钥指纹、签名私钥导出指纹、升级包 SHA-256、上传时间、Leader 节点和控制台验收结果。

## 禁止项

- 禁止只做本地验签就宣布现场可用。
- 禁止按文件名或历史版本号推断现场公钥。
- 禁止为了让某个升级包通过而临时替换现场公钥。
- 禁止覆盖已经交付或已经失败的同名制品。
- 禁止把发布私钥复制到客户现场或控制节点。
- 禁止跳过控制台真实上传，改用直接安装 RPM 代替用户升级路径验收。

## 本次修复要求

1. 使用实验室签名链重新构建，不修改现场公钥以迁就失败制品。
2. 废弃已失败的 `2.2-60` 升级包，不覆盖原文件。
3. 使用新发行序号重新构建 RPM 和升级包。
4. 使用实验室公钥完成本地验签，并与上一版现场已接受包进行签名链连续性核验。
5. 通过完整测试和控制台真实上传后再交付。
