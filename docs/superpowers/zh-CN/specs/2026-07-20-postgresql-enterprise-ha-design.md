## 目标

将 PostgreSQL 从只读兼容适配器提升为一级 ClusterGuard 高可用引擎。交付路径必须涵盖原生发现、候选选择、计划切换、受保护故障转移、原主重新加入、复制修复、节点同步、写入器 VIP 移动、验证、指标、审计、报告和控制台操作。

实现使用原生 PostgreSQL 流式复制。Patroni、repmgr 和供应商 API 是可选的未来提供者，而非依赖项。

## 安全不变量

- `resource_id` 和 `clusterguard.node_id` 识别一个节点；主机名、IP 和端口是可变的端点。
- `system_identifier` 必须在集群的每个成员之间匹配。
- PostgreSQL 提升及其写入器 VIP 转移是一次持久操作。
- 计划切换必须在提升前证明旧主已停止。`default_transaction_read_only` 不被接受为硬性屏障。
- 故障转移需要稳定的故障证据、控制器多数同意、目标租约、已验证的旧主隔离或外部屏障。
- 未知服务状态、不完整的 VIP 探测覆盖、时间线不匹配、暂停重放、未知延迟或未验证的后置条件会失败。
- 跨越提升但无法完成验证的操作是 `indeterminate`，从不成功。
- 代理命令是签名的、计划绑定的、短暂的，并且是白名单允许的。没有通用的 shell 命令端点。

## 组件

### PostgreSQL 适配器

适配器拥有 PostgreSQL 证据和状态转换。它使用 `psql` 进行查询和低风险 SQL，并使用受限节点控制器进行服务级操作。它实现：

- 从恢复、WAL 接收器、重放、时间线和 LSN 证据中获取健康和原生拓扑；
- 通过资格、重放 LSN 和延迟确定候选排名；
- 切换、故障转移、原主重新加入和复制修复计划；
- 不含合成零值的 PostgreSQL 指标；
- 验证一个可写的主节点、流式备节点、时间线收敛、端点所有权和旧主隔离。

### 受限 PostgreSQL 节点控制器

控制器到代理的合同仅暴露以下操作：

- 服务状态、停止和启动；
- 提升配置的数据目录；
- 将备节点指向签名的资源清单源；
- 使用 `pg_rewind` 重新加入；
- 当 rewind 不安全或不可行时，使用 `pg_basebackup` 重建。

每个节点策略固定引擎、集群 UUID、实例 UUID、服务名称、操作系统用户、数据目录、二进制目录、passfile 和允许的端口。源主机和端口包含在签名请求中，并从不可变的操作计划中派生。代理在执行固定参数向量之前，将其与集群策略进行验证。

### 写入器端点

现有的引擎中立 VIP 提供者被重用。它证明完整的拥有者覆盖，获取多数同意的转换租约，移除旧拥有者，证明零拥有者，将 VIP 添加到目标，并验证一个目标拥有者。数据库适配器不能绕过此提供者。

## 计划切换

1. 重新验证资源清单、身份、时间线、WAL 接收器/重放、候选延迟、控制器权限和 VIP 唯一性。
2. 获取端点转换授权和操作锁。
3. 等待候选节点达到采样主节点的 WAL LSN。
4. 通过受限代理停止旧主节点并验证其已停止。
5. 重新检查候选重放 LSN，然后提升它并验证其可写。
6. 将可访问的兄弟节点和旧主节点指向新主节点。旧主节点使用 rewind/重建恢复，而不是不安全的直接附加。
7. 将 VIP 转移到新主节点。
8. 验证一个可写的主节点、一个 VIP 拥有者、健康的备节点和有界延迟；然后进行审计和报告。

## 受保护故障转移

故障转移与计划切换是分开的。它需要稳定的故障窗口、控制器多数同意、选定的最低风险候选、已知的数据丢失风险和旧主隔离。代理路径在可达时停止 PostgreSQL 并移除 VIP。如果主机不可达，必须独立配置的外部隔离器在提升前证明隔离。

## 原主恢复

恢复首先验证目标不可写且不拥有任何 VIP。然后尝试使用 `pg_rewind --write-recovery-conf` 对当前主节点进行操作。节点启动后必须返回恢复状态，从当前主节点身份流式传输，并保持只读。如果 rewind 先决条件缺失或时间线无法收敛，操作将被阻止并推荐重建；破坏性的基础备份替换仅通过显式的节点同步工作流可用。

## 节点同步

通用生命周期 API 变得引擎感知。PostgreSQL 数据节点选择：

1. 对于现有兼容的原主节点，使用 `pg_rewind`；
2. 对于新节点或发散节点，使用 `pg_basebackup`。

生命周期计划记录引擎、源、目标、方法、服务策略和后置条件。元数据仅在原生身份、恢复状态、上游身份和流式健康验证后提交。控制器节点的奇数成员规则保持不变。

## 控制台体验

PostgreSQL 集群使用与 MySQL 相同的集群选择器、拓扑、健康、候选、操作、节点生命周期、元数据、指标、审计和报告界面。按钮由能力驱动。配置的 PG 执行路径暴露真实操作；不完整的节点策略显示确切的阻塞原因，从不产生模拟成功。

## 验证

- 单元测试覆盖 SQL 解析、计划完整性、状态机顺序、幂等进度、签名代理请求、命令白名单、隔离、rewind/重建选择、指标和故障语义。
- 工作流集成测试证明每个变更通过安全、锁、审批、验证、审计和报告阶段。
- 运行时/API/控制台测试证明凭证、能力、引擎特定生命周期和用户面向的控制。
- 完整的 Go 测试、竞态测试、vet、构建、JSON 验证和 diff 检查控制交付。现场破坏性资格认证是环境特定的，从不从单元测试中推断。
