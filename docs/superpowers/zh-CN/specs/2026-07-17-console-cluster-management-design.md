# 集群守护高可用控制台集群管理设计

<!-- LANGUAGE-SWITCH -->
> **语言：** [English](../../specs/2026-07-17-console-cluster-management-design.md) | 简体中文
<!-- /LANGUAGE-SWITCH -->

## 目标

在集群守护高可用控制台中添加一个仅管理员可访问的集群管理对话框。管理员可以从一个或多个种子数据库端点注册集群，并且可以在不删除数据库数据或历史审计证据的情况下，将选定的集群从主动管理中退役。

## 选定方法

集群选择工具栏增加一个紧凑的 `集群管理` 按钮。该按钮打开一个聚焦的模态框，包含两个视图：

- `新增集群`：数据库引擎、不可变的显示名称，以及一个或多个种子端点。提交使用现有的 `POST /api/v1/clusters` 协议，并立即请求新集群的发现。
- `退役集群`：依赖关系摘要和精确的显示名称确认。提交使用新的 `DELETE /api/v1/clusters/{resource_id}` 协议。

退役操作将集群从活动资源注册表和发现调度器中移除。它会移除实时实例、端点、高可用端点元数据、复制链接、指标、拓扑观察和元数据异常。它不会联系数据库主机、停止 MySQL、从操作系统中分离虚拟 IP 或删除数据库数据。

审计事件、报告、已完成的生命周期任务和操作记录仍然存储，以便可以审查过去的操作。退役审计事件记录集群 UUID、显示名称、操作员和移除的资源数量。

## 安全规则

当以下任一条件为真时，退役操作将被阻止：

- 确认文本与集群显示名称不完全匹配；
- 集群存在未过期的操作锁；
- 集群存在未过期的高可用所有权租约；
- 存在计划中、排队中、运行中或验证中的生命周期任务；
- 当前正在运行数据库操作。

过期的协调记录会随着活动资源清单一起被删除。历史操作、审计、报告和终端生命周期任务保持完整。

只有经过身份验证的平台管理员可以注册或退役集群。现有的会话、CSRF、多数Leader和变更权限控制适用于两个端点。

## API

现有注册：

```http
POST /api/v1/clusters
Content-Type: application/json

{
  "display_name": "mysql-orders",
  "engine": "mysql",
  "endpoints": [
    {"hostname": "mysql01", "ip_address": "192.168.102.152", "port": 3306}
  ]
}
```

新退役：

```http
DELETE /api/v1/clusters/{resource_id}
Content-Type: application/json

{"confirm_display_name":"mysql-orders"}
```

成功退役返回退役集群的身份以及移除的实例、端点、高可用端点、链接、指标和异常的数量。冲突的活动工作返回 HTTP 409。集群不存在返回 HTTP 404。

## 控制台行为

模态框可通过键盘访问，响应式设计，并在小屏幕上保持页脚可见。注册支持在提交前添加和删除端点行。至少需要一个端点和一个有效的端口。

注册后，控制台选择新集群，触发发现，并刷新所有视图。如果注册成功但发现失败，集群仍然注册，模态框报告必须重新尝试发现。

退役后，控制台关闭模态框，刷新集群列表，选择下一个可用集群，并报告结果。破坏性按钮在精确输入集群显示名称之前保持禁用。

## 超出范围

- 删除数据库文件、模式、用户或 MySQL 服务；
- 从操作系统接口分离虚拟 IP；
- 删除历史审计、报告、操作或已完成任务记录；
- 批量删除集群；
- 浏览器中自动填写凭据。
